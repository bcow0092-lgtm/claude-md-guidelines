# CLAUDE.md 行为规范

[English](README.en.md)

一份给 AI 编码助手用的行为规范，可以直接作为 Claude Code 的 `CLAUDE.md` 使用。它要求 AI 先核实再动手、只改必要的代码、用实际运行的检查结果说话，并且遇到错误时显式失败，不用 fallback、mock 或默认值掩盖问题。

## 文件

| 文件 | 说明 |
|------|------|
| [CLAUDE.md](CLAUDE.md) | 中文版规范 |
| [CLAUDE.en.md](CLAUDE.en.md) | 英文版规范，内容与中文版一致 |

## 使用方法

选一个语言版本，放到下面任一位置。使用英文版时，把文件名改成 `CLAUDE.md`。

- **全局规则**，对所有项目生效：`~/.claude/CLAUDE.md`（Windows 上是 `%USERPROFILE%\.claude\CLAUDE.md`）
- **项目规则**，只对当前项目生效：项目根目录下的 `CLAUDE.md`

如果用的是读取 `AGENTS.md` 的工具（例如 Codex），把文件改名为 `AGENTS.md` 放到项目根目录即可。规范里没有只针对 Claude Code 的内容。

## 设计思路

**适用范围。** 全局规则会在每个会话里加载，包括纯问答。所以开头说明了测试要求和完成报告只针对改代码的任务，而"不编造""无法核实的不当作事实"这类规则在所有会话里都生效。

**1. 先验证，不猜测。** AI 最常见的问题是凭记忆写出不存在的函数、参数或配置项。这一节要求它先读源码、查真实定义、核对实际安装的库版本。

**2. 简单且精准。** 限制改动范围：不擅自加功能和抽象，不做无关重构，不删自己不理解的代码，危险操作先确认。目的是让 diff 只包含任务需要的改动，便于审查。

**3. 以验证结果为准。** 修 Bug 先写复现测试；测试失败要修根因，不能删测试或弱化断言；没跑过的检查不能说通过。

**4. Fail Fast，禁止静默兜底。** 这是这份规范最有特点的部分。AI 为了"让代码跑起来"，常常加 try/except 吞掉异常、在配置缺失时填一个默认值、接口失败时返回空数据。这些写法让表面上没有报错，却把真正的问题藏了起来。这一节禁止这类做法，并划清了例外：业务明确要求的降级、测试里的 mock、"未登录""无结果"这类正常业务分支都不受限。最后一条要求 AI 每次审查 diff 后主动报告有没有引入这些内容，让兜底逻辑无法悄悄混进代码。

**5. 最终回复。** 固定汇报格式，让你一眼看到改了什么、验证了什么、还有什么没验证。

## 按需修改

这份规范是通用版本，可以根据自己的习惯增删。常见的修改：

- **固定回复语言**：在文件开头加一节，例如：

  ```markdown
  ## 语言

  始终使用简体中文与用户对话。代码注释和 commit message 沿用项目现有语言。
  ```

- **配合 superpowers 等插件**：开头"简单任务可直接处理"这一句，优先级高于插件技能里的强制流程。如果你希望简单任务也走插件的流程（例如 superpowers 的 brainstorming），把这一句改成符合你习惯的写法。
- **和工具默认规则重复的部分**：第 1、2、3 节有些规则和 Claude Code 内置的默认行为重复。只用 Claude Code 且想节省上下文的话，可以删掉；跨工具使用时建议保留。
